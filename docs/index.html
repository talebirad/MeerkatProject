Meerkat Application Back-End Documentation

Introduction

This document introduces the design and use of the classes in the back-end division of the Meerkat application. None of these classes interact directly with the GUI; they are accessed via an API.

Data Structure

Meerkat has a core data structure that encompasses both graphs and message threads. The graph structure is divided into interfaces and their implementations:

  • IGraph<V,E> – Basic graph functionalities.
  • IGraphElement – Common features for vertices and edges.
  • IVertex – Specific to vertex functionalities.
  • IEdge<V> – Specific to edge functionalities.

A DynamicGraph implementation manages extra information (e.g., timestamps) for dynamic data.

Text Data Structure

  • HNode – Represents any message within a thread.
  • MsgNode<A,L,C> – Contains author, location, content, and date information.
  • AnalyzedMsg – Wraps a message with sentiment or emotion analysis results.

Common Classes

  • Attributable – Manages attributes for any entity.
  • Identifiable – Assigns a unique MeerkatId to instances.
  • Weighable – Manages weights associated with entities.
  • Selectable – Supports selecting elements (used for GUI interactions).

Algorithms

  • Community Mining Algorithms: (e.g., AttributeValueMiner, LocalCommunityMiner).
  • Graph Algorithms: Connected components, shortest paths (e.g., Dijkstra), centrality measures.
  • Layout Algorithms: (e.g., RandomLayout, CircleLayout, COMCLayout).
  • Text Analysis Algorithms: For text similarity and sentiment/emotion analysis.
  • Utility Algorithms: Such as Sort and PlainTextParser.

Input/Output (I/O)

  • io.lgorithmutility – Utility classes used by some algorithms.
  • io.graph – Readers and writers for various graph formats.
  • io.text – Readers and writers for message thread formats.
  • io.utility – Application-specific I/O classes.

Project

A project in Meerkat encapsulates multiple graphs or message data sources, linking to various data files and managing outputs.

Main Application

The main.MeerkatApplication class initializes the system, manages active projects, and connects to server-side processing via main.MeerkatServer.

Configuration

Configuration settings are handled by classes such as MeerkatClassConfig and MeerkatSystem.

Tests

Tests for all components are located in the test package.

Algorithm Logic

This guide explains where and how to implement your clustering algorithm in MeerkatProject. Locate the algorithm processing class in MeerkatProject/MeerkatLogic/src/algorithms/communitymining/ and create a new file (e.g., NewAlgorithm.java). Your algorithm processes vertex IDs and assigns clusters (using a modulus operation in this example) before updating the UI.
